# API・仕様変更

開発者向けのAPI（Claudeをプログラムから使うための仕組み）に関する追加・変更・廃止と、Claude Code の設定・動作仕様の変更をまとめています。新しい順に並んでいます。

> **非エンジニアの方へ**: Anthropic Python SDK の項目はプログラムを書く人向けの技術的な変更です。Claude Code の項目は、設定ファイルや管理設定を使っている場合に影響することがあります。

---

### [Claude Code] 許可モード未設定の一部環境では自動モードで起動
**バージョン**: v2.1.283 | **日付**: 2026-09-25

他社クラウド経由（Bedrock・Vertex・Foundry など）や利用状況の送信（テレメトリ）をオフにしている環境では、許可モードを設定していない場合、対話セッションが自動モード（Claudeが安全性を判断して操作を進めるモード）で始まるようになりました。`permissions.defaultMode` を設定していればそちらが優先されます。

---

### [Claude Code] 管理者が使えるモデルをより細かく制限できるように
**バージョン**: v2.1.283 | **日付**: 2026-09-25

組織の管理設定に `availableModelsMatch`（`"exact"` にすると、一覧に書いたバージョンだけを許可し、新しいモデルは追加するまで使えない）と `deniedModels`（特定のモデルを禁止）が追加されました。

---

### [Claude Code] プロジェクト設定では利用状況の外部送信を有効にできなく
**バージョン**: v2.1.282 | **日付**: 2026-09-24

プロジェクトの設定ファイル（`.claude/settings.json` など）に書かれた OpenTelemetry（利用状況を外部に送る仕組み）の送信先や送信内容の設定は、無視されるようになりました。無視された設定は起動時の通知と `/status` で確認できます。

---

### [Claude Code] 以前保存した努力度は新しいモデルに引き継がれない
**バージョン**: v2.1.280 | **日付**: 2026-09-22

`/effort`（Claudeがどれだけ時間をかけて考えるかの設定）がモデルごとの設定になる前に保存した値は、Opus 5.5 のような新しいモデルには適用されなくなりました。新しいモデルは、自分で選び直すまで標準の値で動きます。

---

### [Claude Code] 自動モードの安全判定がサーバー側で行われるように
**バージョン**: v2.1.278 / v2.1.281 / v2.1.282 | **日付**: 2026-09-19〜2026-09-24

自動モードで操作が安全かを判定する仕組み（分類器）が、多くの環境で標準でサーバー側で動くようになりました。サーバー側の判定には判定分の利用料がかかりません。`CLAUDE_CODE_AUTO_MODE_SERVER=0` で従来の手元での判定に戻せます。`/status` に「Auto mode server」の行が追加されました。

---

### [Claude Code] TaskOutput ツールを廃止
**バージョン**: v2.1.277 | **日付**: 2026-09-18

バックグラウンド作業の出力を読むための TaskOutput ツールが廃止され、出力ファイルを Read で読む形に変わりました。これに伴い `taskOutputMaxChars` 設定と `TASK_MAX_OUTPUT_LENGTH` は効果がなくなりました。

---

### [Anthropic Python SDK] レート制限のグループ表記を変更
**バージョン**: v1.7.0 | **日付**: 2026-09-18

レート制限（一定時間に使える回数の上限）の情報に、表示名つきのグループ（`group` と `display_name`）が追加され、従来の `group_type` は非推奨（今後なくなる予定）になりました。

---

### [Claude Code] Monitor の監視に必ず期限が付くように
**バージョン**: v2.1.271 | **日付**: 2026-09-14

Monitor（処理の完了などを見張る機能）の監視には、必ず期限（最長30分、`-p` 実行では10分）が付くようになり、期限が来ると監視をかけ直すようClaudeに通知されます。期限なしで監視する `persistent` オプションは廃止されました。

---

### [Claude Code] プラグインを自動評価する `claude plugin eval`
**バージョン**: v2.1.269 | **日付**: 2026-09-11

プラグイン開発者向けに、`claude plugin eval` でプラグインの評価テストを実行し、点数付きで再現性のある結果（JSONとHTMLのレポート）を得られるようになりました。v2.1.283 からは git 2.31 以上が必要です。

---

### [Claude Code] タスク管理ツールは旧モデルでのみ提供
**バージョン**: v2.1.268 | **日付**: 2026-09-10

作業の進み具合を記録するツール（TaskCreate・TodoWrite など）が、Claude 3.x・Opus 4.0〜4.7・Sonnet 4.0〜4.6・Haiku 4.5 でのみ提供されるようになりました。それ以外のモデルで使うには `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` を設定します。

---

### [Anthropic Python SDK] ツールや返答の受け渡しが簡単に
**バージョン**: v1.5.0 | **日付**: 2026-09-10

メッセージを送る関数（`messages.create` など）に、ツールのオブジェクトをそのまま渡せるようになりました。受け取った返答を次のリクエスト用の形に変換する `Message.to_param()` も追加されました。重複送信を防ぐための `idempotency_key` オプションは、何もしない非推奨の項目になりました。

---

### [Claude Code] 努力度の上限を管理者が決められる設定
**バージョン**: v2.1.267 | **日付**: 2026-09-09

`maxEffortLevel` 設定で、努力度（考える時間の長さ）の上限を決められるようになりました。モデルごとの指定もでき、Bedrock・Vertex・Foundry でも有効です。利用者は上限より低い値を選べます。

---

### [Claude Code] プロジェクトの設定では確認省略モードを既定にできなく
**バージョン**: v2.1.257 | **日付**: 2026-09-01

プロジェクト内の設定ファイル（`.claude/settings.json` など）に `defaultMode: "bypassPermissions"`（確認をすべて省くモード）を書いても無視されるようになりました（`"auto"` と同じ扱い）。使う場合は個人の設定か管理設定に書くか、起動時に `--permission-mode` で指定します。

---

### [Anthropic Python SDK] 組織管理・利用状況レポート向けAPIの追加
**バージョン**: v1.3.0 / v1.4.0 | **日付**: 2026-09-01 / 2026-09-04

組織のコンプライアンス（法令・規程対応）設定やユーザープロフィールを扱うAPIが追加・更新されました（v1.3.0）。利用状況レポートでは、Slack版Claude（Claude Tag）の利用分やユーザーごとの内訳を見られるようになり、ワークスペースIDを指定できる場面も増えています（v1.4.0）。

---

Managed Agents 向けのAPIに、multiagents・outcomes・webhooks・vault validation への対応が追加されました。
